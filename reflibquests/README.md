# Reflib Quests

A quest mod for Minecraft 1.12.2 (Cleanroom) built on reflib. It is an **independent implementation** inspired by FTB Quests; it contains none of that mod's code, and it is not affiliated with or endorsed by FTB. LGPL-2.1-only.

## Using the upstream art (optional)

Put the FTB Quests jar of your choice (1.20 or newer, any loader) into `<game folder>/reflib-supplied/`. Nothing else is needed; the quest map then uses its shapes and lock icon. Without it the mod works with plain squares.

## Status (milestones M1-M3 of Phase 5, plus follow-ups)

| Part | State |
|---|---|
| Quest model (`model`): chapters, quests, tasks, rewards, reward tables, dependencies, visibility, sequential tasks, repeatables, linear/flexible progression, per-team progress, reward claiming, progress save format | Done, unit-tested (19 + 6 tests). Pure Java, no Minecraft types |
| Importer (`io.UpstreamImporter`): upstream quest folders, latest `.json5` and older `.snbt`, translations | Done, unit-tested (5 tests) on hand-written sample folders. **Not yet tried on a real quest pack** |
| Id map: a built-in table of 322 item and 6 entity names of newer versions (colours, wood types, stone variants, flowers, heads, discs, fish, renamed blocks and items) mapped to 1.12.2 names with damage values; your `config/reflibquests/id_map.snbt` entries are added on top and win | Done. Unit-tested (8 tests) and **every entry checked against the real 1.12.2 item and entity registries by the server smoke test** (names exist; damage values are real variants), with a negative control showing the check catches wrong entries. Deliberately **not** covered: things that do not exist in 1.12.2 (netherite, stripped logs, bamboo, newer mobs...); those tasks stay inert and `/rquests problems` lists them. Not covered: spawn eggs, potions and other NBT-based items, tags, banner patterns. The table comes from the known flattening rules, not from a real pack: expect gaps once a real pack is tried |
| Server (`game`): load, per-team progress saved in the world, autosave, task detection, rewards, auto-claim, notifications, Forge events (`api.QuestEvents`), `/rquests` commands | Done. **Verified in game** (dedicated-server smoke test; singleplayer by the user on a hand-written sample pack: item, xp, kill, checkmark, consuming item with id map, choice/random rewards, command reward, auto-claim, persistence across rejoin) |
| Task types detected | item, checkmark, xp, kill, advancement, dimension, location, custom. **Advancement, dimension and location are implemented but were not exercised in game.** Not supported (imported, shown, never progress): stat, observation, biome, structure, fluid, energy, interaction, game stage |
| Reward types granted | item, xp, xp_levels, command, toast (chat message), advancement, custom, random, all_table, choice. **Advancement and all_table rewards were not exercised in game.** Not supported: loot, currency, game stage |
| Sync (`net.QuestNet`): quest book sent on join and after reload (compressed, chunked by reflib), team progress snapshot after each change (at most once per tick), claim/check/hand-in actions from the client re-validated on the server | Done. **Verified with a dedicated server and two real clients** (localhost, 2026-11-19): both received the 1506-quest book (30 KB packed, more than one network frame) intact, both reconnected and received it again, and the server saved two separate per-player progress files (one player's completed quest did not appear in the other's file). Unit-tested wire codec (5 tests). **Not tested:** shared team progress (no party teams yet), a client on another machine, build-mismatch handling between real jars, many players. Progress is re-sent as a full snapshot, not as differences. All quest data, including hidden quests, is sent to every client |
| Questbook screen (`client`): header with progress count, Claim all and Close; chapter list, pannable/zoomable map with dependency lines and state colours, detail panel with tasks, progress bars, check / hand in / claim / choice buttons; opens with J or `/rqbook` | Built and used by the user in game. Problems the user reported were fixed and then confirmed fine by the user on screen, including in the two-client session: icons overlapping the detail panel, choppy dragging (now follows the frame rate), icons not scaling with the quest square (now proportional, 72% of the square). Limits: squares only (shapes ignored), no chapter images or quest links, detail panel does not scroll, placeholder art |
| Shared team progress with party teams (`reflibteams`, separate mod) | Verified with two real clients: the party's progress is stored under the party's team and used by both members; membership changes re-send the new team's progress. The user confirmed on screen that the second member's book showed the shared progress. Not tested: three or more players, kicks and disbands while online, restart persistence of parties during play |
| Search and pinning: Ctrl+F or the magnifier searches visible quests by title, subtitle, description and id (hidden quests are never searchable) and jumps to the result; a pin button in the detail panel pins up to 10 quests per player (saved in the world, sent to the client on join); pinned unfinished quests are tracked in the top-right corner of the screen while playing, and a pinned quest that completes shows a light-green check and green text for 2 seconds, then leaves the tracker | Done. Search ranking and pin rules unit-tested (10 tests). **Verified in game by the user**: search, pinning, the tracker and its completion effect. Not tested: pins with two players, a very long search result list, non-English keyboard layouts in the search box |
| Art from a player-supplied FTB Quests jar (`reflib-supplied/` folder, reflib `SuppliedAssets`): quest shapes (circle, square, diamond, hexagon, octagon, pentagon, heart, gear, rsquare, none) as tinted background plus outline; locked icon; check mark on completed quests; alert badge on quests with rewards ready; header icons for Close and Claim all | Done. Optional: without the jar, or for a texture it lacks, plain coloured squares and text buttons are used and no notice is shown. **Verified in game with the real `ftb-quests-neoforge-26.1.2.10.jar` supplied by the user** (looks right to the user); the jar is not in this repository and nothing from it is copied. Other upstream textures (pin, search, info, settings, arrows, panels, chapter images) are not used yet. Licence: that mod is All Rights Reserved; this is a distribution model, not a clearance |
| Exporter (write quest folders back), editor, party teams | Not started |

Format reference: `../docs/upstream-quest-format.md`. Build and test: `./gradlew :reflibquests:build`.

Known interpretation to verify against real packs: the meaning of the "flexible" progression mode (tasks may progress before dependencies are met, completion waits for them).
